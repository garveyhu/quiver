# 方向 1:沉浸活世界

I now have the full picture. I have read the real scene, pose machine, shell layout, palette, FX, props inventory, worker states, budget/XP wiring, and the transcript. My design below is grounded entirely in these real components and data flows. Here is my complete design proposal for the 「沉浸活世界」 direction.

# Quiver UI 设计方向:「沉浸活世界 / Living Workshop」

把整个界面变成一个**有空间、有时间、会呼吸的夜班工作室**。不是"场景 + 浮在上面的网页面板",而是**世界即界面**:每条数据都在世界里有一个物理位置,每个交互都是在世界里"做一件事"。我读完了实际代码(`StudioRoom.tsx`、`poseMachine.ts`、`QuiverShell.tsx`、`Hud.tsx`、`Transcript.tsx`、`palette.ts`、props/fx 清单),下面所有东西都钉在真实组件和真实数据流上。

## 1. 针对性批评:当前 UI 具体哪里"像网站",这个方向怎么根治

我对照 `QuiverShell.tsx` 的真实布局逐条点名:

**① 场景是个固定 740×460 的"画"贴在中间,四周一圈死黑。**
`SCENE_W=740 / SCENE_H=460`,`scale = Math.min(...)` 用的是 `contain` —— 窗口一拉宽,场景两侧就是 `PALETTE.night2` 的大片空地,HUD 和右面板悬浮在这片"画框外的真空"里。这正是"网站感"的根源:**世界有边界,UI 在世界之外**。
→ 根治:场景改成**横向可平移、可填满**的"长卷工作室"——墙、地、踢脚线无限平铺,窗口变宽就露出更多工位/角落,而不是露出黑边。HUD 不再"浮在画框外",而是变成墙上的**真实物件**(挂钟、白板、预算油表、XP 灯串)。

**② 三个固定工位 `DESK_X = [92, 344, 592]`,第 4 个任务起就只能显示 `+N 也在忙` 角标。**
并发一旦超 3,工人就"消失到别处",纯文字角标 —— 这是把空间叙事直接放弃了。
→ 根治:工位数随窗口宽度动态增减;溢出的工人不是消失,而是**在大厅里排队走动 / 挤在咖啡角**,可读、可点。

**③ 右侧 `委托队列 Panel` + `工位详情 Panel` 是两个标准卡片竖排,带滚动条、▲▼✕ 文字按钮——这就是个待办列表 widget。**
`className="qv-eventrow"`、`cursor:pointer`、`overflow:ellipsis` —— 和任何 SaaS 的 list row 没区别。
→ 根治:队列**搬到世界里的物理白板(Kanban prop 已存在!)** 上,任务是钉在白板上的便签纸;详情对话不是右侧抽屉,而是**点工人后镜头推近到他的工位,转写从他屏幕"长出来"**。

**④ 底部 `钉委托` 指令栏是个 `position:absolute; bottom:16` 的输入框 + 分段控件 + "钉上去"按钮——典型的网页 composer。**
→ 根治:派活变成一个**空间动作**:在指令栏写完,文字**飞向白板变成便签 → 一个新工人从门口走进来 → 走向空工位坐下**。提交有了"物理后果"。

**⑤ 状态全靠浮层文字传达**(StatTile "运行中/排队"、Banner、Achievement 右上角飘)。
信息不在世界里,在世界**上面盖了一层 HUD 贴纸**。
→ 根治:状态尽量"演"出来——运行中 = 几盏工位灯亮着;预算告急 = 全屋灯光转暖红、霓虹 `</>` 招牌开始闪烁;验证通过 = 那个工位上方升起一面小旗 + 该工人 `cel` 姿态。**HUD chrome 最小化,世界自己会说话。**

一句话:当前是 **"像素画 + 网页控件"**,这个方向要做成 **"可操作的像素世界"**。

## 2. 完整设计:信息架构 + 关键屏 + 自适应

### 2.1 信息架构(三个"空间",不是三个"页面")

现状 `view: 'board' | 'archive' | 'settings'` 是页面切换。新架构保留这三个 view,但重新定位为**同一个工作室里的三个区域 / 视角**:

| view | 空间隐喻 | 取代现状的什么 |
|---|---|---|
| `board` 看板 | **主大厅**(现在的 StudioRoom,扩成长卷) | 看板 |
| `archive` 档案 | **大厅尽头的档案室 / 书架墙**,走过去就是 | 居中单列 Panel |
| `settings` 设置 | **墙上的总控台 / 配电箱 + 账本**(SettingsLedger 已存在) | 居中单列 Panel |

切换不是"换页",而是镜头沿着大厅**横向平移**(`board` → 向右滑到 `archive` 书架墙 → `settings` 是拉出墙上的控制面板)。这给了"同一个世界"的连贯感,而不是三张独立网页。MenuBar 保留(它是顶栏 chrome,合理),但 tab 高亮时底部有一条灯带亮起,呼应"切到那个区域"。

### 2.2 主大厅 = 横向长卷(关键屏)

固定画布废弃。改成一条**可横向延展的工作室长卷**,分区(从左到右):

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ QUIVER · myrepo        [看板] [档案] [设置] [项目]                  🔊  Lv7 ▰▰▰▱│ ← MenuBar(保留),右侧塞 XP 灯串
├─────────────────────────────────────────────────────────────────────────────┤
│  ╱窗户  月光        ┌── 委托白板(Kanban)──┐         挂钟 🕐    霓虹</>           │
│ ░░砖墙░░░░░░░░░░░░░│ 排队 │ 进行 │ 完成   │░░░░░░░░░░░░░░░░  油表[预算]▰▰▱     │ ← 墙=HUD层
│                    │ ▭便签 │ ▭便签│ ▭便签 │                                     │
│ ────────────────  └────────────────────┘  ──────────────────────────────────│
│                                                                                │
│   🪑              工位1        工位2        工位3        工位4      ☕咖啡角     │
│   落地灯         [🧍working]  [🧍tense]   [🧍idle]    [🧍arriving]  [🧍🧍排队] │ ← 地板=工人层
│        🐈‍⬛地毯睡猫                                              🪴绿植         │
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ 踢脚线 ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ │
├─────────────────────────────────────────────────────────────────────────────┤
│  ◧模拟 ◨真实   ▸ 给工人派个活……                              [钉上去 →白板]    │ ← 指令栏=工作台抽屉
└─────────────────────────────────────────────────────────────────────────────┘
```

**三个语义图层(z 轴),对应数据三类:**

1. **墙层(背景,被动状态)** —— 全局只读状态变成墙上物件:
   - `Kanban` prop(已存在!)= **真·委托白板**,任务以便签纸贴在 排队/进行/完成 三栏。
   - `WallClock`(已存在)= 真显示当前时间(夜班氛围)。
   - **预算油表**:新组件 `BudgetGauge`,做成墙上一个圆形仪表盘(像油量表),指针随 `spentDay/nightlyCap` 走,进红区时表盘外圈发红光。复用 `BudgetBar` 的 `pct→green/amber/red` 逻辑,只是换皮成表盘。
   - `NeonSign </>`(已存在)= 系统活跃指示:有任务在跑就稳定亮,预算暂停就闪烁断电感。
   - XP 用 `FairyLights`(已存在的串灯!)做成"经验灯串":等级越高亮的灯越多,升级时整串闪一下 + 新灯点亮。

2. **地板层(中景,活动实体)** —— 工人 = 任务,这是世界的主角。工位数 = `floor(可用宽度 / 工位间距)`,随窗口增减。每个工人头顶气泡(`bubble`)+ 工位灯(亮=running)。

3. **前景层(氛围)** —— 落地灯、地毯、睡猫、绿植、`Dust` 浮尘、`Vignette` 暗角、`MoonBeam` 月光。这些保持现状,负责"温馨夜班"的呼吸感。

### 2.3 自适应策略(直接回应"内容没随窗口流畅自适应")

这是当前最大的硬伤(`contain` 缩放留黑边)。方案:**世界是横向可平移的长卷,垂直方向锁定房间高度等比缩放,水平方向填满 + 平移。**

- **垂直**:房间逻辑高度 `H=460`,`verticalScale = viewportHeight / H`,clamp 到 `[0.8, 2.2]`(像素整数倍优先:1×/2×,用 `image-rendering:pixelated` 保证锐利)。墙、地、踢脚线按这个 scale 渲染,**永远顶天立地,无上下黑边**。
- **水平**:墙/地/踢脚线/砖纹是**可平铺图案**(BrickWall 改成 `repeat-x`,`qv-planks` 已是 CSS 平铺),宽度 = `viewportWidth`,要多宽铺多宽。
- **工位数自适应**:`deskCount = clamp(floor((viewportWidth - 边距) / DESK_PITCH), 2, 8)`。窗口窄(笔记本 ~1100px)显 3–4 个工位;宽屏(2560px)显 6–8 个。比当前死定 3 个强太多。
- **工人 > 工位时**:多出来的工人**走到咖啡角排队**(`coffee`/`idle` 姿态,头顶小队号),而不是变 `+N` 角标。点他们一样能选中看转写。
- **窗口极窄(< 720px,如分屏)**:自动进**"竖屏紧凑模式"**——镜头聚焦单工位 + 白板缩成左侧一条便签栏,指令栏占满底部。这是降级,但仍在世界内,不退化成列表。
- **断点用 `useElementSize`**(已有这个 hook!`sceneSize`)驱动,纯 JS 算,不靠 CSS media query,保证 Tauri 窗口拖拽时**实时**重排。

### 2.4 档案室(archive)

镜头从大厅向右滑到**尽头的档案墙**:一面 `Bookshelf` 墙,每本书脊 = 一次历史任务(颜色 = verified 绿 / failed 红 / verifyFailed 琥珀)。书脊上印任务首词 + 花费。

```
档案墙(向右平移到此)
┌──────────────────────────────────────────────┐
│ 📚║绿║║红║║琥║║绿║║绿║║红║   ← 书脊 = 历史任务  │
│   ║读║║改║║跑║║加║║重║║修║                     │
│   ║R ║║b ║║t ║║f ║║c ║║a ║                     │
│   $0.4 $1.2 ……                                │
│  ────────────────────────────────────────────│
│  抽出一本 → 桌上摊开"事件卷轴" + [▶ 在工坊回放] │
└──────────────────────────────────────────────┘
```

抽出一本书 → 桌上摊开一卷"事件卷轴"(Transcript 复用),底部 `▶ 在工坊回放` 按钮 → 触发 `replay.start(evs)` + 切回 board,**那次运行的工人重新走进大厅重演**(replay 机制已存在,`useReplay`)。

### 2.5 设置(settings)= 墙上控制台 + 账本

`SettingsLedger` 已存在,定位为"墙上账本"。设置项做成**配电箱开关 / 旋钮**风格:预算上限 = 旋钮,默认模式 = 拨杆开关(模拟/真实),verify 命令 = 一张钉在板上的"工坊守则"纸条。仍可滚动,但视觉是"控制台"不是 form。

## 3. 标志性交互(动作 → 反馈,全部贴真实事件流)

每个都给了"在哪、长什么样、怎么动、对应哪个数据/事件"。

### 交互 ①:派活 = 便签飞上白板 + 工人入场(取代"钉上去"按钮的网页感)

- **触发**:指令栏输入 + Enter / 点"钉上去"(`board.enqueue`)。
- **动作链(逐帧,低帧 OK)**:
  1. 输入框文字"收拢"成一张**便签纸 sprite**(amber 底,Transcript 里"你的委托"那个 amber 块的样式直接复用)。
  2. 便签**抛物线飞向白板"排队"栏**,啪一声钉住(`Star` 火花 1 帧 + 轻微下坠回弹)。
  3. 紧接着大厅门口(长卷最左)**一个工人 `arriving` 走入**(`worker_started` 事件来时),走到下一个空工位坐下,姿态切 `idle`→`working`。
- **反馈数据**:便签状态色随 `task.status` 变(queued 灰 → running 蓝边 → verified 绿)。`mode==='real'` 的便签盖一个红色"真"火漆章。
- **现状对比**:现在是输入框 + 一个 console.log 式入队,零物理反馈。

### 交互 ②:点工人 = 镜头推近 + 转写从屏幕长出(取代右侧详情 Panel)

- **触发**:`onWorkerClick(taskId)`(已有回调!现在只是 `setSelected`)。
- **动作**:镜头**平移+轻微 zoom** 到该工位(CSS `transform` 过渡 ~250ms),背景其余部分压暗(`Vignette` 加深 + 失焦),该工位**台灯打亮**。
- **转写呈现**:不弹右侧抽屉,而是从**工人的显示器屏幕里"打字机式"逐行长出** Transcript 内容(output 是工人的话气泡 `SpeechBubble dark`,tool_use 是屏幕上滚的代码行,result/verify 是屏幕下方的状态条)。`verifyOutput` 失败时屏幕**变红闪烁**(复用 Transcript 的红框 verify block)。
- **退出**:Esc / 点别处 → 镜头拉回,房间恢复亮度。
- **现状对比**:现在点工人是右侧弹一个 300px 固定 Panel,典型抽屉,与世界割裂。

### 交互 ③:Bash/跑测试 = 工人"张弓" + 工位绷紧(贴 poseMachine 的 tense)

- **触发**:`tool_use` 且 `isShellTool` → `pose:'tense'`(逻辑已存在!)。
- **动作**:对应工人切 `sweat`/`tense` 姿态(已映射),工位灯**从暖黄转冷蓝**(`screen` 色),头顶冒一滴 `Steam`(复用)。这是"主角在做高风险动作"的世界级提示。
- `result` 事件来 → 工人 `tense` 等校验,头顶气泡显 `等待校验… $x.xx`(bubble 已有此文案)。
- **verify 通过** → 见交互④;**失败** → 工人 `sick` 瘫下,工位灯转红,屏幕弹红框。

### 交互 ④:验证通过 = 升旗 + 火花 + XP 灯串点亮(取代右上角飘 Achievement)

- **触发**:`finished` 且 `verified`(`celebrated` 去重逻辑已有)。
- **动作链**:
  1. 工人 `cel` 姿态(已映射),头顶 `Star` 火花爆一下(`sparkle` 标志已有)。
  2. 工位上方**升起一面小旗**(分支名印在旗上,`task.branch`),旗子是新增的微动效 sprite。
  3. 墙上 **XP 灯串(FairyLights)整串闪一下**,`+100 XP` 飘字从工人头顶升起(不是右上角)。升级时多点亮一盏灯 + 等级牌 `Lv7→Lv8` 翻牌。
- **现状对比**:现在是右上角 `position:fixed` 弹个 Achievement 卡片 4.2s 后消失——完全脱离世界。

### 交互 ⑤:预算告急 = 全屋"断电氛围"(把抽象预算变成可感空间状态)

- **触发**:`budgetPaused`(`spentDay >= nightlyCap` 逻辑已有)。
- **动作**:全屋灯光**统一转暖红**(`LightPool` 的 fill 切 red,`Vignette` 加深),`NeonSign </>` 开始**闪烁/断电**,墙上**预算油表指针压到红区 + 表盘嗡嗡发红光**。工人们陆续切 `coffee` 姿态(停工等额度)。墙上飘一张"今夜额度用尽,等天亮"的便签(Banner 内容,但贴在墙上而非顶部浮层)。
- **解除**:提高上限 / 跨天 → 灯光"啪"恢复暖黄,工人回 `idle`,霓虹稳定。

### 交互 ⑥:拖动便签调度队列(取代 ▲▼✕ 文字按钮)

- **触发**:在白板"排队"栏拖动便签上下排序 → `board.reorder(id, pos)`(逻辑已有,只是现在用 ▲▼)。拖到白板外的"垃圾桶/抽屉"= `board.cancel`(取代 ✕)。
- **反馈**:拖动时便签抬起投影变深,落位时啪一声 + 轻回弹。
- **现状对比**:现在每行三个文字符号 ▲▼✕,纯网页列表操作。

## 4. 像素美术与动效:低帧约束下怎么做出"高级感"

硬约束我尊重:**必须像素、低帧**。但低帧不等于简陋,关键在**布局/留白/层次/光影**这些"静态就高级"的东西,动效只做点睛。

**① 层次靠光影,不靠阴影 blur。**
现有 `LightPool`(screen 混合暖光池)、`MoonBeam`、`Vignette`、`Glow` 已经是对的方向。强化:**每个工位一个独立 LightPool**,工位灯状态(暖黄/冷蓝/红)直接驱动这个光池颜色——光是这套界面唯一的"实时反馈通道",成本极低(改个 CSS 变量)却信息量大。全屋只有 2–3 个主光源,大面积暗部 = 高级。

**② 留白 = 大面积安静的墙和地。**
长卷里工位之间留足空地(绿植、空椅、地毯),不要塞满。信息密度集中在**工位 + 白板**两处,其余是"呼吸区"。这直接反驳"简陋"——简陋是因为元素均匀堆砌没有焦点;留白制造焦点。

**③ 动效分三档,严格限制:**
- **环境微动(常驻,2–4s 慢循环)**:`Dust` 浮尘、`MoonBeam` 轻摆、串灯呼吸、窗外偶尔飘过一颗 `Star`、咖啡 `Steam`。这些让世界"活着"但不抢戏。已有 `qv-a-floaty`/`qv-a-steam` 动画类,复用。
- **状态过渡(事件驱动,200–300ms)**:镜头平移/zoom、灯色切换、便签飞行、姿态切换。用 CSS `transform`/`opacity` transition,GPU 友好,Tauri webview 扛得住。
- **庆祝点睛(一次性,< 1s)**:火花 `Star` 爆、升旗、XP 灯串闪、升级翻牌。低帧逐帧但只播一次,显得"郑重"而非"廉价循环"。

**④ 像素锐利度**:全场景 `image-rendering: pixelated`,缩放只用整数倍(1×/2×),避免当前 `Math.min` 任意小数 scale 导致的像素糊边(现在 740/某宽度会出现 0.83× 这种糊掉的缩放)。

**⑤ 调色板已经很好**(`palette.ts` 的夜班暖色系),不动。新组件全部从 `PALETTE` / `cssVar` 取色,杜绝硬编码(也符合你 react 规范里"禁止硬编码颜色")。

## 5. 真实数据 → 界面位置映射(逐项落地)

| 数据 / 状态 | 真实来源 | 落在世界哪里 | 怎么呈现 |

## 6. 与众不同的亮点

1. **「界面即工作室」——UI chrome 几乎全物化进世界。** 预算是墙上油表、XP 是灯串、队列是白板便签、状态是灯光颜色、详情是工人屏幕。打开 Quiver 不像打开一个 dashboard,像**推门走进一间还亮着灯的夜班办公室**。这是没有任何监工/agent 工具做过的定位。

5. **档案 = 可重演的记忆宫殿。** 历史不是表格,是档案墙上一排书脊(颜色即结果);抽出来能让那次运行的工人**重新走进今晚的大厅重演一遍**(replay 已有)。把"历史记录"做成了空间化的、可回放的记忆,而不是冷冰冰的 log 列表。

# Quiver 设计方向：【指挥中心 / Mission Control】

> 一句话定位：把 Quiver 从"一张漂亮的像素画 + 旁边贴了几个网页面板"重做成一个**像素 CRT 指挥台**——整个窗口是一块发光的控制台金属板，工作室场景是嵌在控制台正中的"主观察窗"，所有数据是焊在同一块金属板上的仪表、示波器、灯带和轨道，而不是悬浮在画面之上的网页卡片。

---

## 1. 针对性批评：当前 UI 具体哪里"简陋 / 像网站 / 不现代"

我看了真实运行窗口（`/tmp/quiver-shot.png`）和 `QuiverShell.tsx`，问题不是"美术差"——美术其实很好——而是**布局心智是网页的，不是控制台的**。逐条：

**① 场景被"contain 居中"困死，形成大片死黑letterbox。**
`QuiverShell.tsx:160` 用 `scale = Math.min(w/740, h/460)` 等比缩放 + `translate(-50%,-50%)` 居中。后果就是截图里看到的：场景上下/左右一圈纯 `night2` 死区。窗口越大，死区越大。这是网页"图片居中"的做法，不是游戏的做法。**指挥中心方向根治**：场景不再是一张要"完整看见"的图，而是控制台的**主观察窗 (main viewport)**——它该 `cover`（铺满中央区，边缘被控制台金属框压住、允许裁切），死区由**控制台外壳本身**（仪表、轨道、灯带）填满，且这些外壳是承载真实数据的，不是装饰。

**② 面板是"贴上去的网页 div"，和场景零空间关系。**
看截图右侧"委托队列 (23)"——它就是一个 `position:absolute` 的白边深色 `div`，里面 23 行 `qv-eventrow`（`QuiverShell.tsx:316`），每行一个 emoji 状态点 + 文字 + 两个 `StatusTag`。这跟任何 SaaS 后台的表格行没有区别，"融合度低"正源于此：队列里的任务 ≠ 场景里的工人，用户得在脑子里自己连线。**根治**：任务不是列表行，是**轨道上排队的料件**；正在跑的任务 = 场景里那个工人头顶的工位标签；队列 = 通往工位的传送带。数据和空间是同一个东西。

**③ HUD 是六个孤立数字块，没有"实时感"。**
`StatTile`（运行中/排队/今夜花费/已完成）+ `XpBar` + `BudgetBar` 一字排开（`QuiverShell.tsx:271`）。它们只显示**当前标量**，没有**时间维度**——而 Quiver 最有戏的恰恰是"整夜运行"的时间流：费用怎么爬升、token 怎么烧、几点钟谁验过了。静态数字 = 仪表盘照片；指挥中心要的是**活的示波器**。**根治**：费用/ token 做成 **sparkline 走线**，状态做成**徽章矩阵**，事件做成**自上而下流动的时间线**。

**④ "钉上去"指令栏是个孤立的网页输入框。**
底部 `min(640px, 100%-340px)` 宽的输入条（`QuiverShell.tsx:356`），截图里是空的、孤零零浮在底边。它没有"派遣"的仪式感，就是个 search box。**根治**：做成控制台的**派遣槽 (dispatch slot)**——一张实体"委托卡"被吸进传送带、滑向空工位，有物理反馈。

**⑤ 自适应只有一档（等比缩放），信息密度不随窗口变。**
窗口拉大，什么都不变，只是 letterbox 变大；窗口缩小，面板会盖住场景。没有响应式的"信息密度分级"。指挥中心方向天然要分级（见 §2.3）。

## 2. 完整设计

### 2.1 信息架构：一块控制台，三圈信息环

抛弃"菜单栏 + 看板/档案/设置 tab 切换整页"的网页式 IA。指挥中心是**单屏常驻 + 抽屉/模态下钻**：

```
┌──────────────────────────────────────────────────────────────────────┐
│  ▣ QUIVER  ·  realtime-voice            [● LIVE 02:14]    Lv12 ▰▰▰▱  ♪ │  ← 标题轨 (status rail)
├───────────┬──────────────────────────────────────────┬────────────────┤
│ LEFT       │              MAIN VIEWPORT                │  RIGHT          │
│ 指挥仪表盘  │          (工作室场景 = 主观察窗 cover)      │  事件时间线      │
│ (gauges)   │                                          │  (event stream) │
│           │   ┌──────┐  ┌──────┐  ┌──────┐           │                 │
│ 预算环     │   │工位1 │  │工位2 │  │工位3 │           │  02:14 ▸worker  │
│ token走线  │   │ 🧑‍💻  │  │ 🧑‍💻  │  │ 💤  │           │  02:14 ⚒ Edit   │
│ 状态矩阵   │   └──┬───┘  └──┬───┘  └──────┘           │  02:13 ⚒ Bash   │
│ 迷你地图   │      ╿ tense    ╿ working                │  02:11 ✓ verify │
│           │   ════════════════════════════ 传送带      │  02:09 ▸worker  │
├───────────┴───────────────[ 派遣槽 ]──────────────────┴────────────────┤
│  [模拟│真实]  ▏给工人派个活…                         ▏ ⟶ 钉上去          │  ← 派遣轨 (dispatch rail)
└──────────────────────────────────────────────────────────────────────┘
```

整窗是一块**控制台金属板**（一个统一的 `qv-console` 容器，自带内嵌斜面高光 + 螺丝点 + 极淡扫描线），三个分区不是浮动 div，而是被金属**分隔条（rivet seam）**切出的"焊接舱格"——左中右共面、同一光照、同一像素栅格。这是"融合"的关键：没有任何东西"浮"在场景上，所有东西和场景在同一块板上。

- **标题轨 (top status rail, 高 ~36px)**：左 logo + 项目名；中 `● LIVE` 心跳指示 + 本次运行时长计时；右 XP 等级条 + 声音。`档案 / 设置 / 项目`从顶部 tab 降级为标题轨右侧的**小图标按钮**，点开是**从右侧滑出的抽屉**（不再整页切换，保持指挥台常驻）。
- **左舱：指挥仪表盘 (left gauge bay, 宽 ~200px)**：预算环、token/费用 sparkline、状态徽章矩阵、迷你地图。详见 §5。
- **中舱：主观察窗 (main viewport, flex 占满)**：工作室场景 `cover` 铺满，工位上是工人，工位下方一条**传送带**承载排队任务。
- **右舱：事件时间线 (right event rail, 宽 ~260px)**：全工人事件流的统一时间线（垂直 LED 走带），见 §3.2。
- **派遣轨 (bottom dispatch rail, 高 ~52px)**：模拟/真实分段 + 输入 + 钉上去，做成实体派遣槽。

### 2.2 关键状态的布局

**(a) 空工坊（无任务）**：传送带空转、灯带呼吸、左舱仪表归零但"通电"（指针在 0 位轻微抖动）。派遣槽有一行引导文案在槽口闪烁："把第一张委托卡推进传送带 →"。不是网页式的空状态插画。

**(b) 满载（并发 > 工位数）**：当前 `hallOverflow` 那个右上角小角标 `+N 也在忙`（`QuiverShell.tsx:303`）太弱。改为：超出 3 个工位的工人，在传送带**入口处排成料件队列**，每个料件是一张缩小的委托卡，带迷你状态灯。一目了然"还有几个在门口等工位"。

**(c) 预算闸触发（暂停）**：不再是顶部红 Banner（`QuiverShell.tsx:289`）。改为**整块控制台进入"断电预警"态**：预算环变红并`qv-flick`闪、传送带停转并叠红色"⏸ 预算到顶"丝印、所有工人 pose 切到 idle/coffee。视觉上是"系统被自己的保险丝跳闸"，符合 DESIGN §10 的"夜间断电"心智。提高上限的按钮焊在预算环正下方（哪坏修哪），不是飘在顶部。

**(d) 单工人下钻（点工人/点料件）**：右舱事件时间线**从"全部工人"过滤为"这一个工人"**，并在顶部钉一张**工位档案卡**（prompt、模型、分支、累计费用/turn/token、verify 结果）。这取代当前那个浮动 `Transcript` Panel（`QuiverShell.tsx:341`）。下钻是右舱的内容切换，不是新弹一个面板——保持单屏。

### 2.3 自适应策略：信息密度三档（不是等比缩放）

控制台按窗口宽度切**密度档**，主观察窗永远 `cover` 吃掉剩余空间（场景永不留死黑边）：

| 窗口宽 | 档位 | 左舱 | 右舱 | 主观察窗 |
|---|---|---|---|---|
| ≥ 1180px | **指挥台 (full)** | 全仪表（环+走线+矩阵+地图） | 全时间线 | cover，3 工位全见 |
| 820–1180px | **紧凑 (compact)** | 仪表竖排压缩，地图折叠成一行点 | 时间线保留，档案卡折叠 | cover，工位可能裁边 |
| < 820px | **专注 (focus)** | 左舱收成一条 **40px 灯带导轨**（只留预算环 + 状态点），点击展开为浮层 | 右舱收成抽屉（标题轨上一个 `▸事件` 触发） | 场景吃满，工人放大 |

实现上是 CSS container query / `useElementSize`（项目已有 `useElementSize` hook，`QuiverShell.tsx:54`）切 class，不是 JS 算 scale。主观察窗内部场景用 `cover` 算法（`Math.max` 而非 `Math.min`），并把视觉重心（工位行）对齐到容器中下部，保证裁切裁的是天花板而不是工人。

## 3. 标志性交互（动作 → 反馈，全部贴真实事件流）

**① 派遣一张委托卡（dispatch → 上传送带）**
动作：在派遣槽输入 prompt、选模拟/真实、回车/点"钉上去"。
反馈：一张像素**委托卡**（prompt 首行 + 模/真色标）从派遣槽**被吸起**（`qv-pop` + 上移），滑入传送带尾部排队。当 `worker_started` 事件到达（真实后端真的起进程了），卡片**滑到一个空工位并"立起来"变成工位标签**，对应工人播 `arriving` walk-in。真实模式先弹现有的确认 Dialog（`QuiverShell.tsx:421`），确认后才吸卡——危险动作的仪式感保留。
这一条直接把"队列里的料 = 场景里的工人"焊死，根治批评②。

**② 事件流脉冲（event → 三处同时亮）**
每来一条 `AgentEvent`，**三个地方同帧响应**：右舱时间线顶部插一行新 LED（`qv-slidein`，项目已有此 keyframe）；对应工人头顶气泡更新 + pose 切换（`tool_use`→working、`error`→sick、Bash→tense，沿用 `poseToState`）；左舱对应 sparkline 走线**推进一格 + 末端亮点闪一下**。一条事件 = 一次全台联动，这是"实时感"的核心。`output_chunk` 高频，时间线侧做合并节流（沿用后端的 coalesced emitter 心智，DESIGN §3），只让气泡和 sparkline 动，不刷屏时间线。

**③ 费用 sparkline 实时爬升 + 预算环逼近闪警**
`result.costUsd` 累加进左舱**费用走线**（横轴=时间，纵轴=累计 $），同时**预算环**（环形进度，绿→琥珀→红，沿用 `BudgetBar` 配色逻辑）随之收紧。当 `barSpent/barTotal` 越过 0.85，预算环边缘开始 `qv-flick` 急闪 + 环心显示剩余额度倒数。越过 1.0 触发 §2.2(d) 断电态。这把 DESIGN §10 那个"看不见的美元天花板"变成**台上一圈会逼近、会跳闸的保险丝环**。

**④ 工位下钻（点工人/料件 → 右舱聚焦 + 连线）**
点中央任一工人或传送带上的料件：该工人**描边高亮**（`qv-glowpulse`），从工人到右舱**画一条像素连接线**（一格一格点亮，约 6 帧），右舱时间线**过滤成该工人**并钉上工位档案卡。再点空白/Esc 取消（沿用现有 Esc 清 selected，`QuiverShell.tsx:88`）。下钻是"把摄像头对准这个工位"，不是弹窗。

**⑤ verify 闸开合（finished → 闸门动画）**
`finished` 事件到达时，工位标签下方一道**像素闸门**演出：`verified` → 闸门绿光开启 + 工人 `celebrate` `qv-hop` + XP 飘字（`qv-rise`）+ 该工人的料件**沿传送带驶出右侧"已合并出口"**；`VerifyFailed` → 闸门红光关闭 + 工人 `sick` + 料件**退回到一条"待人工复核"侧轨**（不消失，因为 DESIGN §G6 明确失败要留人看），点它在右舱档案卡里展开 `verifyOutput`。把"合并 vs 打回"从一个文字 StatusTag 变成**台上看得见的闸门开合 + 料件分流**。

**⑥ 时间线擦洗回放 (scrub replay)**
档案里"回放"那次运行（项目已有 `useReplay`，`QuiverShell.tsx:120`）时，右舱时间线变成一条**可擦洗的轨道**：拖动时间游标，主观察窗里的工人 pose、左舱 sparkline、费用环**全部回到那个时刻的状态**。指挥中心做"时间机器"——这是 mission-control 最有掌控感的招，且完全复用现有 replay 事件数组。

## 4. 像素美术与动效：低帧约束下怎么显得"高级"

硬约束是像素 + 低帧。指挥中心方向恰恰**吃这个约束**——真实的军用/航天控制台本来就是离散指示灯、阶梯式仪表、隔行 CRT，全是"低帧 + 量化"的美学。具体手法：

- **统一光照与材质把"网页 div"变成"焊在一块板上"**：整个 `qv-console` 外壳用现有调色板的 `night/night2/wall/ink` 做金属，舱格用 `inset 0 0 0 2px wall` 内描边（项目通用做法，`pixel.css:157`）+ 顶部 1px `glow` 高光 + 底部 1px `ink` 阴影，营造"折弯钢板"的斜面。所有舱格共用这套，视觉自然连成一体，根治批评②的"贴上去感"。
- **留白即"控制台底板"**：网页留白是空白，控制台留白是**有纹理的金属底板**（极淡 2px 网格丝印 + 偶尔一颗螺丝 `Px` 点 + 一条扫描线 `qv-pulse`）。死黑 letterbox 问题（批评①）由此消解——空间从来不空，是台面。
- **层次靠"发光的活物 vs 暗的台面"**：台面（金属、丝印）压暗压灰；数据元素（指示灯、sparkline 末端点、工人气泡、闸门光）用 `amber/green/blue/red/neon` 高饱和**自发光**（`box-shadow: 0 0 4px currentColor`，沿用 `qv-mini-dot` 的发光做法，`pixel.css:251`）。明暗对比建立"台面 vs 信息"的层次，信息密度高但不糊。
- **低帧微动效清单（全部 2–4 帧、`steps()` 量化，复用现有 keyframe）**：
  - 心跳 `● LIVE`：`qv-flick`（已存在）2 帧闪，跟随有事件到达的节奏，没事件时慢呼吸 `qv-pulse`。
  - sparkline 推进：每来一个数据点整条线**整格平移一步**（`steps`），末端点闪一下——不做平滑曲线（平滑=非像素=掉档次）。阶梯折线本身就是像素美学。
  - 状态徽章翻牌：工人状态变化时徽章做 2 帧"翻转"（scaleY 1→.15→1，复用 `qv-blink` 思路）。
  - 传送带：底纹用 `steps(4)` 横向平移的虚线，营造"链条在动"，CPU 几乎零成本。
  - 闸门：开/合各 3 帧 sliced sprite，不是补间。
- **节制动效**：同屏最多让"有新事件的那一个工位 + 它的 sparkline + 时间线第一行"动，其余静止。低帧 + 局部动 = 既高级又不晕，也符合 DESIGN 对"做不到高帧动画"的诚实。

## 6. 与众不同的亮点

1. **整窗是一块焊死的控制台，不是"场景 + 浮层"。** 这是和另外两个方向（沉浸场景 / 拟物）最本质的区别，也是直接对症"像网站""融合度低"的解药——物理上不存在"浮在画面上的面板"。

2. **传送带把"任务队列"和"工人精灵"合并成同一个物体。** 料件 → 上工位 → 出合并口 / 退复核轨，task 的整个生命周期是台上一条**看得见的物理路径**。当前 UI 里队列和工人是两套互不相干的东西，这是最大的"游戏感"增量。

3. **预算环 = 会跳闸的保险丝。** Quiver 的灵魂是诚实的美元治理（DESIGN §1.3/§10），把这个抽象天花板做成台上一圈逼近会闪警、越线会让整台"断电"的环，是把产品最硬核的卖点变成最有戏的视觉——别的方向很难做到这种"机制即视觉"。

4. **一条事件三处同帧联动 + 可擦洗时间线回放。** 实时是"全台脉冲"，复盘是"时间机器擦洗"。这套"实时 + 回放共用同一条时间线"是 mission-control 独有的掌控感，且完全复用现有 `events` 数组和 `useReplay`。

5. **低帧像素恰好是控制台美学的本体。** 离散指示灯、阶梯 sparkline、隔行扫描、翻牌徽章——本方向不是"在像素约束下勉强做现代"，而是**用像素约束去逼真还原一类本来就离散、低帧的高级物件（航天/军用控制台）**，把硬约束变成风格资产。

# Quiver UI/UX 设计 ·【环境陪伴】方向

> 设计前提:所有内容已对照真实代码——`poseMachine.ts` 的 6 态状态机、`agentEvent.types.ts` 的事件契约、`StudioRoom.tsx` 的场景构成、`palette.ts` 的 39 色、`pixel.css` 的 ~25 个 keyframe(`qv-breathe/blink/hop/sway/floaty/pulse/rise/glowpulse…`)、`useStats/useTaskBoard/useSupervisor` 的数据出口。下面每一处都落在这些真实出口上,不是视觉稿。

核心心智:**这不是一个仪表盘,这是一个房间。** 你不是"管理任务列表",你是"晚上把活留给一屋子工人,然后回来看他们干得怎么样"。环境陪伴方向的全部设计,都是在强化"这个房间是活的、有人在里面、随时间在呼吸"这件事。

---

## 1. 针对性批评:当前 UI 为什么"像网站"

我把当前 `QuiverShell.tsx` 逐块对照了,问题不在"像素画得不好"(场景其实很丰富),而在**像素场景是一张静止的壁纸,真正的信息全堆在浮在它上面的矩形面板里**。具体:

1. **场景是死的背景板,数据是活的前景。** `StudioRoom` 740×460 被 `scale = Math.min(w/740, h/460)` 整体缩放居中(line 160),四周留黑边;真实信息(`StatTile`/`委托队列 Panel`/`Transcript`)全是 `position:absolute` 浮在它上面的 HUD 卡片。结果:**场景和数据是两层贴在一起的纸,没有任何耦合**。这正是"网站套像素皮"的根因——像素只是壁纸。环境陪伴方向的根治:**让数据长在场景里**。预算是壁炉的火,队列是公告板上的纸条,工人头顶气泡就是 transcript 的最新一句——删掉右侧那块浮动 Panel,把它"种"进房间。

2. **整体 letterbox 缩放 = 永远不沉浸。** `scale` 用 `Math.min`(contain),窗口一宽就左右黑边、一高就上下黑边。用户原话"该全屏沉浸占满"。根治:**场景改为"无限横向房间 + 垂直 cover"**——墙和地板的纹理可平铺,宽窗口=看到更多工位(更多并发),不是看到更多黑边。

3. **三个固定工位 `DESK_X = [92, 344, 592]`,第四个工人就溢出成角标 "+N 也在忙"(line 303)。** 这是把"游戏"降级成"列表分页"。环境陪伴方向:工位数应该跟着 `maxWorkers` 和窗口宽度长出来,溢出的工人不是消失成数字,而是**"在隔壁房间"**——有门、有从门缝透出的光。

4. **没有时间感。** 应用叫"整夜运行",但界面永远是同一个深夜。`palette` 里有 `amber/glow/screen/moon` 一整套光,却只用来画固定场景。陪伴感的灵魂就是时间流逝——根治见 §2 的昼夜系统。

5. **庆祝是个弹窗,不是事件。** 现在验证通过 → 右上角弹 `Achievement` 卡片 4.2 秒(line 99–117)。这是 SaaS toast。环境陪伴方向:庆祝应该**发生在那个工人身上**(他原地 `qv-hop`、撒 `qv-conf`、桌上亮一颗星挂到墙上),房间记住它,而不是一张飞过的卡。

6. **"安睡模式"完全缺席。** 这是整夜挂机产品最该有的、当前 0 实现的东西。见 §3.5。

### 2.3 自适应策略(根治 letterbox)

把场景从"固定 740×460 等比缩放"改成**分层响应式**:

| 层 | 当前 | 改为 |
|----|------|------|
| 后墙纹理 (`BrickWall`/地板 `qv-planks`) | 固定宽 740 | **CSS `background-repeat` 横向平铺**,填满窗口宽。砖墙、地板本来就是 tileable 纹理。 |

## 4. 像素美术与动效:低帧约束下怎么"高级"

约束是低帧(产品做不到高帧),陪伴方向把它变成优势——**低帧 + 缓动 + 光影 = 安静、精致、不廉价**。具体手法:

1. **昼夜光照系统(最大的"高级感"杠杆)。** 现有 `palette` 有 `night/night2/amber/glow/moon/screen` 全套。做一个 `useTimeOfDay()` hook(纯前端,读系统时钟),输出一个**主色温变量**注入 `:root`:
   - 傍晚:墙偏暖橙(`amber` 多);深夜:偏冷蓝(`night2`);凌晨:最暗+月光 `MoonBeam` 最亮;清晨:`glow` 渐入、窗外泛白。
   - 实现成本极低:只改几个 CSS 变量值,所有现有组件(用 `var(--qv-*)`)自动跟着变。**一套像素资产,四种时段气质**——这是用最少资产换最大"它在活着"感的关键。

2. **层次 = 景深 + 留白。** 后墙(数据陈设)、中景(工位工人)、前景(壁炉/睡猫/扶手椅)三层。前景轻微 `blur(1px)` + 暗角 `Vignette`(已有)聚焦中景工人。**留白靠地板**——别再把工位铺满,工位之间留出地板呼吸,溢出去隔壁房间。

3. **光池呼吸。** 已有 `LightPool`(screen 混合)+ `qv-pulse`。让屏幕光池颜色**跟随工人状态**:`working`=蓝(`screen`)、`tense`=红、`celebrate`=绿。地面反光跟着变——**整个房间的氛围光是数据驱动的**,这是廉价做不到的"高级"。

4. **微动效全用 `steps()` 和长缓动,杜绝线性丝滑。** 像素的高级感恰恰来自**克制的不连续**:打字手 `qv-tap .42s`、眨眼 `qv-blink 4.2s`、尘埃 `qv-floaty 6s`。新增动效都遵守这个节奏(2–6s 周期、ease-in-out 或 steps),**绝不做 60fps 平滑位移**——那才显廉价。

5. **庆祝/失败的色彩克制。** 撒花只用 palette 里 4 色(`CONFETTI_COLORS` 已是 amber/pink/blue/green);失败不用刺眼纯红弹窗,用 `qv-swirl` 暗绿 + 屏幕转 `red` 微光 + 纸条红边。**情绪价值靠"安静地被记住",不靠喧闹。**

## 6. 与众不同的亮点(5 个)

1. **「房间会过日子」昼夜光照。** 一套像素资产,靠注入色温变量在傍晚/深夜/凌晨/清晨呈现四种气质——你能从屏幕色温知道现在几点、工人挂了多久。竞品(任何 agent 监工/CI 面板)都是恒定主题,这个**有时间**。

2. **「夜巡安睡模式」专为整夜挂机设计的第二形态。** 把"长时间不盯着看"从缺陷变成卖点:降帧省电、大字远观、柔和近况浮现、点击开灯唤醒。这是产品定位("整夜运行")的直接形态化,目前 0 实现。

3. **「壁炉即预算」。** 美元预算是 Quiver 的治理核心,把它从进度条变成会熄灭、会冒烟、会让全屋变暗的火——**用户会对它产生情绪**(舍不得火灭),这是预算治理最好的 UX:不是数字,是温度。

4. **「星图」累积式成就。** 验证通过的星永久挂在后墙,整夜跑完早上回来,墙上的星空就是昨晚战绩。成就**沉淀在场所里**,不是飞过的 toast——延迟满足的具象化。

5. **「工人有作息和性格」。** 喝咖啡、点头、摸猫、从门口走进来、idle 太久伸懒腰。房间在你不操作时也活着——这是"陪伴"二字的字面兑现,也是把 6 态 pose 机 + 现有 `coffee/Cat/qv-bob` 资产**复用到极致**、几乎零新美术成本的设计。

# Quiver 设计方向:【键盘效率流 / The Quiver Cockpit】

> 一句话定位:**把 Quiver 从"鼠标点点的像素网站"变成一架可以闭眼飞的驾驶舱**——⌘K 是引擎,vim 导航是操纵杆,深夜工作室是挡风玻璃外的星空。重度用户整夜不碰鼠标也能派活、追流、过 verify、翻档案。

---

## 1. 针对性批评:当前 UI 到底哪里"简陋 / 像网站 / 不现代"

我读完 `QuiverShell.tsx` 后的诊断,逐条对应代码,不空谈:

**① 场景是"贴在背景上的图",不是世界。** `StudioRoom` 用 `SCENE_W=740 / SCENE_H=460` 写死,再 `Math.min(w/740, h/460)` 等比 `contain` 居中(L160)。结果:窗口一放大,场景四周全是 `night2` 黑边,中间一张邮票大的房间。这是典型的"画布思维"而非"舞台思维"——**沉浸感被 letterbox 黑边直接杀死**。键盘流的根治:场景退成**全屏铺满的环境层(cover 而非 contain,允许裁切)**,前景信息层浮在它之上,场景永远占满挡风玻璃。

**② 三块浮层各自为政,像三个独立的网页 widget 钉在一张图上。** 左上 HUD(L271)、右侧委托队列+对话(L310)、底部指令栏(L356)——三组 `position:absolute` + 各自 `boxShadow`,没有统一的栅格、没有共享的焦点系统、互不知道对方存在。`zIndex` 手撸成 5/6/7/20/60/70。用户说的"跟网站一样、融合度低"精确命中这里:**它们是漂浮的 div,不是一个有结构的 HUD**。

**③ 交互全是鼠标点击,键盘是事后补丁。** 现有 keydown(L73-96)只有 ⌘N / 1/2/3 / ? / Esc 六个,且**逻辑散落在一个巨型 useEffect 里**;任务上移/下移/撤回只能用鼠标点那三个 `▲▼✕` 字符(L331-333),对话面板只能点工人或点队列行切换。**没有命令面板、没有焦点环、没有行内键盘操作**——这对一个"整夜运行的监工工具"是致命的:重度用户想快速 triage 五个跑飞的任务,得拿鼠标一个个戳。

**④ 信息密度与层次靠"堆 StatTile"硬凑。** 六个 `StatTile` 平铺(L272-283),每个都是同样的 `0 0 0 2px wall, 0 0 0 4px ink` 描边盒子,没有主次。预算闸暂停这种**关键状态**和"已完成 3"这种**背景数字**视觉权重一样。现代感的缺失=层次的缺失。

**⑤ 状态切换没有过渡,是硬跳。** `setView` 直接换 DOM,`setSelected` 直接显隐 Panel(L341)。`qv-pop`/`qv-slidein` 这些 keyframes 在 pixel.css 里**已经定义好了却基本没用上**。键盘流最讲究"焦点的连续性"——闪现/聚焦/退出都该有 80–140ms 的像素步进动效,否则快速操作时眼睛跟不上焦点去哪了。

**键盘效率流如何根治这五条**:场景变成全屏氛围层(治①);所有信息层收进一个**统一的 HUD 框架 + 一个可吸附的右栏(Rail)**,共享栅格与焦点系统(治②);**⌘K 命令面板成为一切动作的单一入口** + vim 导航 + 行内键盘操作(治③);用**主次分明的"仪表组"**替代平铺 StatTile,关键状态升格为顶栏脉冲(治④);给焦点移动、面板进出、命令面板召唤统一加**像素步进过渡**(治⑤)。

## 2. 完整设计:信息架构 + 关键屏 + 自适应

### 2.1 信息架构:三层 z-stack,一个焦点系统

抛弃"6 个 absolute div 各占一角"。整个 App 是**三层 + 一条命令总线**:

```
┌─ Layer 0 · 氛围层(StudioRoom,全屏 cover,pointer-events 受限)
├─ Layer 1 · HUD 框架(顶栏 Strip + 右栏 Rail + 底部 Dock,共享栅格 + 焦点环)
└─ Layer 2 · 召唤层(⌘K 命令面板 / Quick-peek / Toast,模态或半模态)

横切:Command Bus —— 所有动作(派活/导航/reorder/cancel/replay/切项目/改设置)
       都是一条 Command;键盘、命令面板、点击都只是触发它的不同前端。
```

**焦点系统**是这个方向的灵魂。引入一个全局 `focusZone` 概念(用一个 `useFocusZone` hook + Context,符合规约里"跨子树共享低频状态用 Context"):

```
focusZone ∈ { 'scene' | 'rail' | 'dock' | 'palette' | 'peek' }
```

- `g` 键(或 Tab)在 zone 间循环,当前 zone 有一圈 **2px amber 焦点环**(`box-shadow:0 0 0 2px var(--qv-amber)`,复用现有 `qv-input:focus` 的视觉语言)。
- 进入 Rail 后,`j/k` 在任务行间移动,被选行高亮(复用 `selected===t.id` 那行已有的 `background:wall`,升级成 amber 左边条)。
- 这把现状里"散落在一个 useEffect 里的六个快捷键"升级成**一个有结构的、可发现的导航网格**。

### 2.2 关键屏:看板 / The Cockpit(主屏)

与现状的关键差异:

- **Strip(顶栏仪表条,替代左上漂浮 HUD)**:贴顶通栏,左 brand、中段是**主仪表组**(夜间预算条 + XP 条,这两个是"会随时间变化、需要余光监控"的连续量),右段是**三个计数胶囊** `⏵running ⏸queued ✓verified`(离散计数),最右一个常驻 `⌘K` 提示芯片。`◷02:14` 是过夜运行时钟——强化"它在替我熬夜"的心智。**主次出来了**:连续量用条形(占宽、有动画),离散量用胶囊(紧凑),关键告警时整条 Strip 变色脉冲。

- **氛围层全屏**:`StudioRoom` 改 `cover`(`Math.max` 而非 `Math.min`),宽屏时左右多出的墙面/书架/绿植正好填满,**永远没有黑边**。工人精灵锚定在场景底部 1/3 的工位带,场景缩放时工位带跟着等比走但**信息层不缩放**(信息层是真正的响应式 HTML,只有像素美术缩放——这解决了用户痛点①"内容没随窗口流畅自适应")。

- **Rail(右栏,替代两个漂浮 Panel)**:一个**可吸附、可折叠**的右侧栏,上半 QUEUE(委托队列)、下半 FOCUS(跟随焦点任务的迷你转写)。两者共享一个边框、一个滚动域、一套 j/k 导航。`]` 折叠 Rail(场景全露出来欣赏)、`[` 展开。折叠时缩成一条 24px 的"书脊",上面竖排三个计数,hover/聚焦弹回。

### 2.3 关键屏:⌘K 命令面板(本方向的核心,召唤层)

这是"键盘效率流"区别于其他方向的标志性屏。按 ⌘K(或 Dock 里点"⌘K更多")**从屏幕中上方像素步进降下**一块面板,背后场景 `qv-vignette` 加深、轻微去饱和:

```
                ┌─────────────────────────────────────────────┐
                │ ⌘K  › fix las|                          Esc  │ ← 单行输入,光标是像素块
                ├─────────────────────────────────────────────┤
                │ 派活                                          │
                │  ▸ 派活(真实):"fix las…"           ⏎ 真实  │ ← 高亮行,右侧显示该 verb 的快捷键
                │  ▸ 派活(模拟):"fix las…"          ⇧⏎ 模拟  │
                │ 任务                                          │
                │  · #02 fix lasso selection      running $0.4 │ → 选中 = 跳到该工位 + 展开转写
                │  · #07 add dark mode            verified ✓   │
                │ 跳转                                          │
                │  ⌂ 看板   ▤ 档案   ⚙ 设置   ⌥ 切项目…        │
                │ 工坊                                          │
                │  ⏸ 暂停队列   ▷ 恢复   $ 调高夜间预算…        │
                └─────────────────────────────────────────────┘
```

- **零状态(空 query)**:显示"最近动作 + 正在跑的任务 + 高频跳转",让它也能当 dashboard 速览用。
- **有 query**:第一条**永远是"用这段文字派活"**(因为派活是这工具最高频的动作),回车即 enqueue,`⇧⏎` 切模拟/真实。下面 fuzzy 匹配现有任务(prompt 子串)、跳转、工坊动作。
- **任务结果项**直接显示 `status` + `costUsd`(来自 `TaskRecord`),回车=焦点跳到那个工位 + 展开转写;`⌥⏎`=对 queued 任务做置顶 reorder。
- **它是 Command Bus 的总前端**:派活走 `board.enqueue`、跳转走 `setView`、reorder/cancel 走 `board.reorder/cancel`、暂停走"把 nightlyBudget 临时降到 0 或一个 paused flag"、切项目走 `sup.selectRecentProject`、调预算直接深链到设置那一项。**一个面板驱动一切**,正是这个方向的承诺。

### 2.4 关键屏:档案 / 卷轴(Logbook),也走键盘

档案不再是"居中单列面板"(现状 L247),而是**双栏 master-detail**:左栏是 `useArchive().records`(newest-first)的列表,`j/k` 移动、`Enter` 在右栏 lazy-load `loadEvents(taskId)` 渲染完整转写卷轴;`r` = replay(调 `replay.start(events)` 回工坊回放);`/` = 在档案里 fuzzy 搜 prompt。这样**追溯一次跑飞的过夜运行**完全键盘化:⌘K 输 "fix lasso" → Enter 进档案那条 → `r` 在工坊重放那一夜。

### 2.5 自适应策略(治痛点①②)

把"窗口缩放"拆成两个独立尺度:

| 元素 | 缩放方式 |
|---|---|
| 氛围层(像素美术) | `cover` 整数倍优先缩放(`floor` 到最近的 1x/2x/3x,避免像素糊),允许裁切,永远铺满。工位带锚底。 |
| 信息层(Strip/Rail/Dock/命令面板) | **真·响应式 HTML**,不缩放、只重排。字号/间距用固定像素(保持像素风锐利),靠断点改布局。 |

**三档断点**:
- **宽(≥1100)**:Strip 全展开(预算+XP 都显示)、Rail 默认展开、Dock 居中留白。
- **中(720–1100)**:Strip 收起 XP 条为一个小胶囊、Rail 可折叠、Dock 通栏。
- **窄(<720)**:Rail 自动折叠成书脊、Strip 只留预算条+计数、命令面板宽度贴边。**键盘流在窄窗反而更香**——反正一切都能 ⌘K,小窗也能全速操控。

这套"美术层 cover 缩放 + 信息层响应式重排"是对用户痛点①②③的统一回答:场景沉浸铺满、信息层流畅自适应、面板不再是漂浮 widget 而是有断点的结构化 HUD。

## 3. 标志性交互(动作 → 反馈,全部贴真实事件流)

**① ⌘K「即说即派」**(招牌)。任意时刻 ⌘K → 打字 → `Enter`。面板像素步进降下(`qv-pop` + translateY,3 帧 steps)。回车瞬间:面板**向 Dock 方向收拢消失**,同时**一个 amber 像素"委托纸团"从屏幕中央飞向右栏 QUEUE 顶部**(复用 `qv-fall`/`qv-rise` 的位移语言),队列顶部新行 `freshIds` 闪一下(`useTaskBoard` 已经吐 `freshIds`,现成的!)。**没有任何鼠标移动,任务已经在队列里了。** 这是整个方向"心流"感的核心镜头。

**② vim 式 triage 焦点环**。`g` 进 Rail,`j/k` 在 QUEUE 行间走,当前行亮 amber 左边条。在 queued 行上:`J/K` 直接 reorder(调 `board.reorder`,行带着动画上下滑一格)、`d d` cancel(行向右划出 + 灰化,`board.cancel`)、`Enter` 展开该任务转写。在 running 行上 `Enter` = 焦点跳到对应工位精灵(场景里那个 worker 跳一下 `qv-hop` 表示"看我")。**五个跑飞的任务,十秒内键盘 triage 完。**

**③ 工人头顶气泡 = 活的 output_chunk 流**。现状气泡是静态贴图。改成:每来一个 `output_chunk`,气泡内文字做**打字机式像素步进追加**(steps 动画,不是平滑滚动);来 `tool_use` 时气泡瞬切成 `✎ Bash` 工具芯片样式(蓝色,复用 Transcript 里 `cssVar('blue')` 的 `✎ tool` 语言);`result` 来了气泡变 `等待校验 $0.30`(tense 姿态)。**余光扫一眼场景就知道每个工人在干嘛**——事件流直接演出来,不用点开。

**④ verify 关「红章 / 绿章」时刻**。`finished` 事件到达:verified → 工人 `celebrate`(`qv-hop`+举手+`qv-conf` 彩纸,现成 CSS),Strip 的 ✓ 计数 `+1` 带 `qv-rise` 飘字,XP 条推进一格(`stats.xp`)。VerifyFailed → 工人 `sick`(`qv-sway`+脸变绿),**该工位上方盖下一枚像素"红章"**,Rail 对应行右侧出现红色 `✕verify` 芯片,`Enter` 展开直接看 `verifyOutput`(Transcript 已有红框 verify 块,复用)。**成败有仪式感,失败一眼可追因**。

**⑤ 预算闸「踩刹车」全局反馈**。当 `budgetPaused` 翻 true(`spentDay≥nightlyCap`):整条 Strip 的预算条从 amber **脉冲变红**(`qv-glowpulse` 改红色变体),顶栏降下一条**非模态的红色细横幅**"预算到顶 · 队列已暂停 ⌘K 调高上限",场景里 idle 的工人**集体切 `idle` 慢呼吸**(暗示停工)。⌘K → 输 "预算" → Enter 直接跳到设置那一项。**预算治理这个产品核心卖点,被升格成一个有体感的全局事件**,而非现状一条不起眼的 Banner。

**⑥ Quick-peek 悬浮转写**(半模态)。Rail 太窄看不全转写时,在任意任务行按 `space` → 屏幕中央**像素步进展开一块 Quick-peek 卡片**(完整 `Transcript`,带你的委托气泡 + 输出 + 工具卡 + verify 框),`j/k` 在 peek 内滚动,`space`/`Esc` 收起。**不离开看板就能深读一次运行**,焦点回来时还在原来那行。

## 4. 像素美术与动效:低帧约束下怎么显高级

**留白与层次(治"平铺无主次")**。Strip 用**两级视觉权重**:连续量(预算/XP)用带内发光的条形(占宽、是主角),离散计数用扁胶囊(`qv-tag` 升级,小、靠右、是配角)。Rail 内 QUEUE 行用**斑马纹 + 状态色左边条**(running=amber、verified=green、failed=red、queued=dim),靠左边条颜色一眼分流,而不是现状每行一个 StatusTag 文字。**信息层大量用 `night2`/`wall` 的低饱和深色 + 留白**,让满饱和的 amber/green/red 只出现在"需要你看的地方",对比度即层次。

**光影统一(治"贴图感")**。复用 `qv-vignette`/`qv-pool`/`qv-beam`/`qv-fairy` 已有的氛围 CSS,但让它们**响应状态**:有任务在跑时暖光池(`qv-pool`)更亮更密、串灯(`qv-fairy`)闪得更欢;全部 idle 时灯光转冷、月光束(`qv-beam`)更突出——**房间的光会随工坊忙闲呼吸**。命令面板召唤时给场景叠一层 `vignette` 加深 + 轻微去饱和(CSS filter),把焦点逼到面板上。

**低帧微动效(全部 steps,不要平滑)**。这是像素风的纪律:所有过渡用 `steps(2~3)`,80–140ms。焦点环出现/移动=2 帧跳;命令面板降下=3 帧;气泡打字=steps 步进;reorder 行滑动=3 帧。**低帧不是妥协,是风格**——平滑缓动反而出戏。已有的 `qv-pop/qv-bob/qv-rise/qv-fall/qv-slidein` 足够拼出所有这些,基本不用新写 keyframe。

**像素光标**(`qv-cursor` 已存在但没用)。命令面板/Dock 输入框用**像素方块光标**(steps 闪烁),强化"这是个终端式驾驶舱"的专业感,呼应键盘流定位。

**新增的小美术件**(克制):① 一枚像素"委托纸团"精灵(交互①的飞行物);② 红/绿"印章"精灵(交互④的 verify 章);③ 焦点环作为一个可复用的 `<FocusRing>` 组件(就是 amber box-shadow + 2 帧脉冲)。三件都极小,符合"复用优先、按需新增"。

**关键:几乎不需要新数据**。`freshIds`、`replay`、`verifyOutput`、`hallOverflow` 这些后端早就吐出来了,现状 UI 没充分用。键盘流主要是**重新编排已有数据 + 加一层焦点/命令系统**,落地风险低。

## 6. 与众不同的亮点

**① ⌘K「即说即派」+ 飞行纸团**:派活这个最高频动作做到**零鼠标、一句话、有反馈**——打字→回车→纸团飞进队列。这是其他三个方向不会有的"心流派活"镜头,直接回应"更现代化更有交互感"。

**② 焦点是一等公民,而非鼠标的附庸**:全局 `focusZone` + vim 网格 + amber 焦点环,让"我现在控制的是哪块"永远可见、可跳。这是"专业工具感"的来源,把它和"像素办公室小游戏"的可爱缝在一起——**可爱的皮 + 专业的骨**。

**③ 事件流被"演"出来,而不是被"读"出来**:工人头顶气泡是活的 output_chunk/tool_use/result,场景灯光随忙闲呼吸,verify 盖红/绿章。**余光监控整夜运行**——这正是"监工"工具该有的体感,纯文字 dashboard 给不了。

**④ 美术层 cover 缩放 ⊥ 信息层响应式重排**:两个尺度彻底解耦,根治"内容不自适应/场景不铺满"。窗口怎么拖,场景永远铺满无黑边、信息层永远锐利不糊、键盘流在任何尺寸都全速。

**⑤ 低帧 steps 动效作为风格宣言**:不追求 60fps 平滑(产品本就做不到),而是把**像素步进的 2–3 帧跳变**做成一致的设计语言——焦点跳、面板降、气泡打字、行滑动全是 steps。**把技术约束变成识别度**,这比假装流畅更高级。
