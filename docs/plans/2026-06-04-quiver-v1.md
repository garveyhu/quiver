# Quiver v1 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build Quiver v1 — a macOS Tauri app that orchestrates headless Claude CLI agents as a gamified pixel office, per `docs/DESIGN.md`.

**Architecture:** A pure-Rust `quiver-core` crate (runner trait, event model, supervisor logic — Tauri-agnostic, fully unit-testable) wrapped later by a Tauri shell (Rust core ↔ React/Phaser UI via `invoke`/`emit`). The first-principle equation: `1 task = 1 git worktree = 1 detached `claude -p` process = 1 pixel sprite`. We build **bottom-up**: prove the process→event bridge in pure Rust first, then layer worktree/verify/merge, then the Tauri + Phaser UI, then budget + sandbox.

**Tech Stack:** Rust (tokio, serde, serde_json, async-trait, thiserror, anyhow), Tauri 2.x, React + TypeScript + Phaser, SQLite (rusqlite), git worktrees, macOS Seatbelt.

**Reference:** Full design at `docs/DESIGN.md`; `§N` below points to its sections.

**Plan shape (honest):** Phase 0–1 are detailed to bite-sized TDD steps — that is the immediate, well-understood work and where to start. Phases 2–6 are task-level outlines with goals + exit criteria; they get expanded to bite-sized steps **when reached**, because (a) several behaviors are empirically **UNVERIFIED** until the Phase 0 spike (`§16 Q1`: the real post-2026-06-15 `claude -p` cost/limit/error shape), and (b) UI/sandbox detail is best pinned down closer to execution. Detailing them now would be false precision.

**Cross-cutting rules (every phase):** test-first (TDD); the **`fake-claude` binary is the primary test driver** — the real `claude` costs real money post-2026-06-15 (`§13`), so it appears only in gated manual smoke tests; commit frequently using Angular commit format; DRY/YAGNI.

## Phase roadmap & exit criteria

| Phase | Goal | Done when… |
|---|---|---|
| **0. Core bridge (pure Rust)** | Spawn `claude -p`, parse stream-json, emit normalized `AgentEvent`, print them | A pure-Rust demo runs a real `claude -p` task and prints a clean, ordered `AgentEvent` stream; parser + adapter unit-tested against fixtures and the `fake-claude` binary |
| **1. Worktree + run-in-worktree (Rust)** | One task → worktree → spawn agent **inside** the worktree → events → deterministic cleanup | Core creates `quiver/task-<id>/attempt-<n>` worktrees, runs the agent there, tears them down safely; all git-metadata ops serialized behind one mutex (`§6`) |
| **2. Verify-gate + merge (Rust)** | tests-green→merge else mark-for-review; parallel merge re-verify | 2–3 parallel tasks merge safely into `main` with re-verify-against-merged-main; conflicts → `NEEDS_REBASE`, never auto-resolved (`§7`) |
| **3. Tauri shell + IPC** | Wrap core in Tauri; `invoke`(create task) / `emit`(AgentEvent); packaged-app PATH + `claude` resolution | A built `.app` **launched from Finder** finds `claude`, runs a task, streams events to a minimal HTML view (`§12`) |
| **4. Phaser pixel office** | `AgentEvent` → sprite state machine; the 5 sprite states | Workers appear / type / coffee / sweat / celebrate / sick driven by real events; office replays from the SQLite event log on restart (`§5.5`, `§11`) |
| **5. Budget governance (dollar)** | Sum `cost_usd`, hard-pause before cap, overflow opt-in (default OFF) | Queue hard-pauses at the budget; budget-paused surface (no countdown) is distinct from the rate-limit coffee countdown (`§10`) |
| **6. Sandbox + watchdog + persistence + report** | Seatbelt sandbox (load-bearing, fail-closed), classify-before-restart watchdog, SQLite source-of-truth, morning report | Every agent (and the verify-gate) runs inside Quiver's Seatbelt profile; watchdog routes purely on normalized enums (`§8.3`); morning report lists merged/blocked/failed/spend (`§9`,`§8`,`§11`) |

> **Spike gate:** Finish Phase 0 Task 0.3 (capture real stream-json) **before** finalizing Phases 5–6 detail — the credit-exhaustion / rate-limit / cost event shapes drive the budget governor and watchdog, and they are currently assumptions (`§5.3`, `§16 Q1`).

```rust
mod tests {

    #[test]
    fn worker_started_serializes_flat_camelcase() {
        let ev = AgentEvent {

        assert_eq!(v["taskId"], "t1");                // camelCase envelope

}
```

**Step 2 — Run it, expect FAIL** (types don't exist): `cargo test -p quiver-core event::` → Expected: does not compile / FAIL.

**Step 3 — Implement the minimal types** (start with only what Phase 0 needs; grow later per `§5.2`):
```rust
use serde::Serialize;

#[derive(Clone, Debug, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct AgentEvent {
    pub task_id: String,
    pub seq: u64,
    pub ts_ms: i64,
    pub runner: RunnerKind,
    #[serde(flatten)]
    pub payload: AgentEventPayload,
}

#[derive(Clone, Copy, Debug, Serialize)]
#[serde(rename_all = "snake_case")]
pub enum RunnerKind { ClaudeCli, CodexCli, AnthropicApi }

#[derive(Clone, Copy, Debug, Serialize)]
#[serde(rename_all = "camelCase")]
pub enum AuthMode { Subscription, ApiKey, OpenAiEndpoint }

#[derive(Clone, Debug, Serialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum AgentEventPayload {
    WorkerStarted { model: Option<String>, auth_mode: AuthMode },
    ToolUse { tool: String, summary: String },
    OutputChunk { text: String },
    Result { ok: bool, cost_usd: Option<f64>, num_turns: u32 },
    Error { code: String, message: String },
}
```

**Step 4 — Run, expect PASS:** `cargo test -p quiver-core` → Expected: PASS.

**Step 5 — Commit:** `git commit -am "feat(core): minimal normalized AgentEvent wire types"`

## Phase 1 — Worktree + run-in-worktree (Rust)

Goal: turn "run claude somewhere" into "run claude in an isolated git worktree for one task, then clean up." Still pure Rust, still driven by `fake-claude` in tests.

- **Task 1.1 — `GitGuard` metadata lock** (`§6.3`): a struct holding one `tokio::sync::Mutex<()>`; all `worktree add/remove/prune`, branch create/delete go through it. TDD: two concurrent `worktree add` calls on a temp repo both succeed, no `index.lock` error.
- **Task 1.2 — Worktree lifecycle:** `create(task_id, attempt) -> WorktreePath` does `git worktree add quiver/task-<id>/attempt-<n>` on a unique branch; `remove()` gates on `git status --porcelain` (never force-remove a dirty tree, `§6.3`). TDD against a temp repo.
- **Task 1.3 — `gc.auto=0` for the run** + bounded retry/backoff on transient git lock errors. TDD the backoff with a simulated lock.
- **Task 1.4 — Wire it together:** `run_task(task)` = create worktree → spawn runner in it (Phase 0) → drain events → (stub) `Finished{...}` → remove worktree. Integration test with `fake-claude`.
- **Task 1.5 — Crash cleanup determinism** (`§8.4`): on a simulated crash, the worktree is pruned + removed and a failure is recorded. TDD.

**✅ Phase 1 exit:** given a repo + a task, core runs the agent in an isolated worktree and always cleans up deterministically, with git metadata serialized.
