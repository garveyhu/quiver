# Quiver v1.0 规格 — 游戏场景化的交互、配置、信息管理

> 整夜自主构建的北极星。每个构建子代理动手前先读本文件 + `docs/DESIGN.md`。
> 用户睡觉期间推进;醒来 review + 迭代。**默认 simulate 模式,绝不擅自花真 Claude 额度。**

## 目标(用户原话提炼)
把 Quiver 从"能跑的雏形"推到一个**高质量 v1.0**:更流畅的系统交互;更顺的**配置**与**信息查看**;系统该有的**基础配置**、**持久化策略**,以及 **AI 输入输出管理 / 对话管理 / 任务管理**。
**核心约束:这些信息的交互方式与存储方式都从"游戏场景"角度设计——不能纯网页表单/管理后台的感觉。**

## 设计原则(灵感调研后定的)
**"游戏化的皮 + 清晰的交互"——混合式 UI,不为主题牺牲可用性。**
- **Diegetic/世界化外壳**用在叙事性强的地方:任务=墙上**公告板的委托**、对话/日志=**卷轴/档案库**、设置=**一本账本/墙上控制台**、完成=撒花飘字。
- **但密集数据/配置保持清晰**(Stardew 设置菜单组织差,我们反过来**分组清楚**):清晰图标 + **悬停 tooltip** 给上下文 + 可读排版。
- 全程 Stardew cozy 调性(暖木/羊皮纸/柔光)、流畅过渡与 juice、journal 有更新会"闪"提示。
- 复用已有真素材(`~/Documents/image/resources/quiver/`:背景图/桌子图/元素集1(黑底需抠)/元素集2(透明)/4 个弓箭手)。

## 五大模块(游戏场景化)
1. **系统设置/配置** — 一个 cozy 的"设置账本/墙上控制台",分组清晰、可搜:模型、预算/月度额度上限、默认模式(simulate/real)、并行工人数、agent 二进制路径、fake 节奏、主题、UI 缩放。存 `quiver-store`(settings 表)。
2. **持久化策略**(`quiver-store` 长出来):settings 表;**完整事件日志**(§11 的 `agent_event` 真相表——每条 AgentEvent 落库、可回放);task 表(队列+状态+历史);按项目配置。一切可持久、可回看。
3. **AI 输入输出管理** — 落库并**丰富地查看**每次运行的完整 I/O:prompt、每个工具调用(命令/文件/参数)、每段输出、result、花费。呈现成**"日志卷轴/Logbook"**——可打开、可滚动**回放**一次运行,不只是摘要行。
4. **对话管理** — 每次运行=一条"委托记录/对话";浏览/搜索历史(**档案库/书架**),点开看完整 I/O 日志、花费、状态、分支。
5. **任务管理** — **公告板/任务队列**:可排多个任务(往板上钉委托),看 待接/进行/完成/失败;进行中的在工坊里有 archer 实时干活;可拖拽排序/优先级。

## 流畅交互
悬停 tooltip(Stardew 式)、令人满足的过渡/juice、拖拽、有更新闪烁提示、声音钩子预留。

## 整夜构建计划(按完成通知链式推进;每阶段 screenshot 自检 + 增量提交 + 不 push)
- **A. 持久化地基**:`quiver-store` 加 settings / 完整 `agent_event` 事件日志(每条事件落库,可按 run 回放)/ task 队列表;run 时把每个事件写库。
- **B. 设置面板**:cozy、分组清晰的设置(账本/控制台),接 settings 存储 + 即时生效。
- **C. 任务板/多任务队列**(公告板):排队、状态、拖拽;进行中→工坊 archer。
- **D. 对话/运行档案 + 完整 I/O Logbook 回放**(卷轴/书架)。
- **E. 交互/juice/HUD 打磨 + 流畅过渡** 收尾。

## 质量与诚实
目标是醒来能 review 的高质量 v1.0;但视觉好坏无法盲定 + 可能撞限额——所以**每阶段都 screenshot 自检并增量提交**,保证无论进展到哪都有扎实、可回看的成果,早上一起迭代。
技术底座不变:Tauri(Rust 核 + React/Phaser)+ quiver-store;全程 simulate + fake-claude,不动真 Claude;Angular 提交、Co-Authored-By。
